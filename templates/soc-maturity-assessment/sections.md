# SOC Maturity Assessment: Section Blueprint

Blueprint for a maturity assessment. The user names the model. Do not invent scores or benchmarks.

## Section index

| ID | Section | Include |
|---|---|---|
| MA0 | Cover and Document Control | Always |
| MA1 | Scope and Model | Always |
| MA2 | Assessment Method | Always |
| MA3 | Domain Ratings | Always |
| MA4 | Strengths | Always |
| MA5 | Gaps and Risk | Always |
| MA6 | Target State and Roadmap | Always |
| MA7 | Benchmark Notes | Only when the user supplies benchmark data |
| MA8 | Sign-Off and Acknowledgement | Always |

## MA0: Cover and Document Control

**Purpose:** Identify the document, period, and owner.

**Content blocks**

- Cover with title, period, and classification
- Document control table

**Inputs from the user**

- Document ID format
- Author, reviewer, approver roles

**Data from the SIEM (vendor-neutral)**

- None

**Compliance hooks (indicative, verify before citing):** ISO/IEC 27001

## MA1: Scope and Model

**Purpose:** State what was assessed and against what.

**Content blocks**

- SOC scope
- Maturity model chosen by the user
- Rating scale

**Inputs from the user**

- Model and scale

**Data from the SIEM (vendor-neutral)**

- None

**Compliance hooks (indicative, verify before citing):** ISO/IEC 27001, NIST CSF, SEBI CSCRF 2024

**Writing note:** Use only the model the user names. Do not invent scores or benchmarks.

## MA2: Assessment Method

**Purpose:** Make it credible.

**Content blocks**

- Evidence reviewed
- Interviews or workshops
- Sampling

**Inputs from the user**

- Method

**Data from the SIEM (vendor-neutral)**

- None

**Compliance hooks (indicative, verify before citing):** ISO/IEC 27001

## MA3: Domain Ratings

**Purpose:** Report by domain.

**Content blocks**

- Domains such as people, process, technology, intelligence, governance
- Rating with evidence per domain
- AI governance domain (when AI systems are in scope)

**Inputs from the user**

- Ratings and evidence

**Data from the SIEM (vendor-neutral)**

- Capability evidence from the platform

**Compliance hooks (indicative, verify before citing):** ISO/IEC 27001, NIST CSF, SEBI CSCRF 2024, ISO/IEC 42001

## MA4: Strengths

**Purpose:** Name what works.

**Content blocks**

- Top strengths with evidence

**Inputs from the user**

- Observations

**Data from the SIEM (vendor-neutral)**

- None

**Compliance hooks (indicative, verify before citing):** ISO/IEC 27001

## MA5: Gaps and Risk

**Purpose:** Name what does not.

**Content blocks**

- Gap table (gap, risk, evidence)

**Inputs from the user**

- Observations

**Data from the SIEM (vendor-neutral)**

- None

**Compliance hooks (indicative, verify before citing):** ISO/IEC 27001, SEBI CSCRF 2024, NIST CSF

## MA6: Target State and Roadmap

**Purpose:** Plan.

**Content blocks**

- Target ratings
- Initiatives, owners, dates

**Inputs from the user**

- Targets

**Data from the SIEM (vendor-neutral)**

- None

**Compliance hooks (indicative, verify before citing):** ISO/IEC 27001, NIST CSF

## MA7: Benchmark Notes

**Purpose:** Compare only with data provided.

**Include when:** Only when the user supplies benchmark data

**Content blocks**

- Comparison against user-provided benchmark

**Inputs from the user**

- Benchmark data

**Data from the SIEM (vendor-neutral)**

- None

**Compliance hooks (indicative, verify before citing):** ISO/IEC 27001

**Purpose:** Record organization-level review.

**Content blocks**

**Inputs from the user**

- Sign-off roles

**Data from the SIEM (vendor-neutral)**

- None

**Compliance hooks (indicative, verify before citing):** ISO/IEC 27001
